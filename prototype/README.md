# 第一版手機畫面樣稿

這是一份可點選的設計提案，讓使用者先確認學習體驗，再開發正式功能。暫用「日和 HIYORI」作為樣稿名稱，尚未定稿品牌。

## 開啟方式

直接以瀏覽器開啟 `index.html`，無需安裝套件。也可在此資料夾啟動靜態 HTTP 伺服器：

```powershell
python -m http.server 18088 --bind 127.0.0.1
```

再開啟 `http://127.0.0.1:18088/`。檔案可直接開啟，沒有外部字體、圖片或 API 依賴。

## 畫面與體驗

| 畫面 | 入口 | 可體驗內容 |
| --- | --- | --- |
| 今日首頁 | `#home` | 單一學習任務、複習提醒與生活入口 |
| 五十音 | `#kana` | 一次五字、平片假名切換、字卡與完整表 |
| 字形與筆順 | `#stroke` | あ的三筆動畫、分步觀察與字形記憶提示 |

| 點餐單課 | `#lesson` | 對話、收起答案回想、選句與換詞輸出 |
| 相似字複習 | `#review` | シ／ツ對照、收起提示與回想示例 |

## 容易學習與記憶的設計

- 一次五個字或一個生活任務，不同時堆疊整份課綱。
- 首頁直接指出下一步；每一活動保留一個主要操作。
- 字形、筆順、詞例與生活句串在同一條路徑。
- 先看與描寫，再收起提示回想；描寫與默寫明確區分。
- 使用者能選自己的飲料，將句型連到真實需要。
- 提示用於學習，不用完成率或連續天數製造壓力。

## 樣稿邊界

所有進度與複習數字為示範。手寫軌跡與文字輸入只存在記憶體，重新整理即清除；未接入任何儲存、登入、後端、雲端同步、錄音、真實音檔或自動評分。

筆順示例僅為「あ」。播放音檔按鈕會明確顯示「尚未接入音檔」。檢定與我的頁僅展示後續入口，不代表已實作正式功能。

## 審閱重點

1. 首頁是否能立即看懂今天要學什麼？
2. 五個字與一個任務的份量是否合適？
3. 字形、筆順、描寫到默寫是否順暢？
4. 字體、對比、按鈕大小與手寫區是否舒適？
5. 點餐課是否容易理解、容易回想、願意繼續學？
